Blocks

interface Blocks(source)

Vanilla blocks and custom blocks from all plugins supported by Mimic. Get it via Mimic.blocks. To make your own plugin's blocks available here, implement BlockProvider instead.

Quick start

Key palmLog = Key.key("craftengine:default/palm_log");

// Check the ID read from a config
if (!blocks.hasBlock(palmLog)) { ... }

// Identify a placed block
if (blocks.isBlock(block, palmLog)) { ... }

// Set a block in place of an empty one
blocks.setBlock(location.getBlock(), palmLog, "[axis=x]");

// Break a block with a pickaxe, dropping items on the ground
blocks.breakBlock(block, pickaxe);

IDs

Blocks are identified by Key, which consists of a namespace and a path:

  • The namespace is the ID of the plugin providing the block: minecraft, craftengine.

  • The path is the block within that plugin: stone, default/palm_log.

The namespace is required, there is no search over all plugins. Note that Key.key("palm_log") turns into minecraft:palm_log, so validate block IDs read from configs with hasBlock or against getAllBlocks. Block IDs are separate from item IDs: a block and the item placing it may have different IDs.

Ownership

A block belongs to the plugin with the highest priority that recognizes it, and vanilla blocks belong to minecraft. So a custom block is never recognized as the vanilla block it is built on: a custom block built on a note block is not minecraft:note_block. To check the vanilla block regardless of plugins, use Block.getType.

Rules

  • Call all methods on the main thread (on Folia - on the thread owning the block), since they touch the world.

  • No place or break events are fired and no protection checks are made, the caller is responsible for both.

  • Block IDs may be unknown until their plugins finish loading, and may change when a plugin reloads. Don't validate configs in onLoad, and don't cache results.

  • null or false means "not possible": the block doesn't exist, no plugin recognizes it, or the change failed.
